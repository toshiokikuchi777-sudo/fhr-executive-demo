# FHR 経営者向けプレゼンデモ

架空の3店舗を使った、操作可能な説明用デモです。実際のFHRの数値・店舗情報ではありません。

## 開く

公開デモ：[FHR 経営コンソール](https://toshiokikuchi777-sudo.github.io/fhr-executive-demo/)

GitHub Pagesでログインなしに閲覧できます。ダウンロードした `docs/index.html` をブラウザーで開くと、通信なしでも動作します。

## 説明の順番

最初に「この資料について」が開きます。右上または導入ページの「説明に沿って見る」を押すと、次の6画面を順に確認できます。「デモを見る」から自由に操作することもできます。

1. この資料について：複数店舗の状況をまとめて確認し、次の行動を決める仕組みの提案であることと、今回検討したいことを共有します。
2. 経営概況：売上・利益・会員数を確認。全体は増収でも、店舗ごとに状況が異なることを示します。
3. 店舗の課題：店舗Bの退会率と未対応フォローを確認。両者の因果関係は断定しません。
4. 改善アクション：「担当・期限を決める」を押して、担当責任者と確認期限をデモ内で設定します。
5. 効果を考える：対応完了率、退会率、作業時間を分けて評価。人数と会費の仮定を変え、1か月分の追加会費売上を試算します。
6. 導入プラン：まず1〜2店舗で確認・試行・評価する進め方を説明します。

「次へ」「前へ」で移動できます。自由操作中も左メニューから各画面へ移動できます。`#overview` など既存の各画面への直接リンクも利用できます。デモ内のタスクと試算はメモリー上だけに保持し、リロードまたは「デモをリセット」で初期状態に戻ります。リセット時は導入ページを表示します。

## 範囲

- AI欄は事前作成した表示例で、AIサービスには接続しません。
- タスク登録はデモ内のみで、通知や外部保存は行いません。
- 実際の認証、店舗別認可、会員管理、決済、バックアップは実装していません。
- 90日は導入検討の例であり、納期・効果・費用の約束ではありません。
- 通貨MYRと3店舗は説明用の仮定です。

## 検証

`node --test tests/data.test.cjs` で集計・試算・整合性の9テストを実行します。
`node --check docs/app.js` でUIスクリプトの構文を確認します。

導入ページ追加時に、初期表示、導入ボタン、6画面の移動、説明の開始・順送り・戻る・終了、リセット、既存画面への直接リンク、ブランドリンクを実ブラウザーで確認しました。390pxと320pxの画面幅で、全6画面に横方向のはみ出しがないことも確認済みです。ブラウザーのコンソールエラーはありません。

## ファイル

- `docs/index.html`：画面の共通構造
- `docs/styles.css`：レスポンシブ表示
- `docs/data.js`：架空データと計算
- `docs/app.js`：画面と操作
- `tests/data.test.cjs`：計算の検証

## 公開の更新

GitHub Pagesの公開元は `main` ブランチの `/docs` です。`docs` 内の変更を検証して `main` にプッシュすると、GitHub Pagesが更新されます。秘密情報や実際の顧客データは追加しないでください。
