# LAVICHE / AMZ GROUP 経営者向けプレゼンデモ

株式会社ラ・ヴィーチェ／AMZ GROUPの事業情報をもとに、国内とマレーシアのフィットネス事業を一つの画面で確認する操作デモです。国内AF・マレーシアAF・VISPO24を想定した架空3モデルで、実在店舗の成績やグループ全体の実績ではありません。

## 開く

公開デモ：[LAVICHE / AMZ GROUP 経営コンソール](https://toshiokikuchi777-sudo.github.io/fhr-executive-demo/)

既存リンクを維持するため、公開URLとリポジトリ名は変更していません。GitHub Pagesでログインなしに閲覧できます。ダウンロードした `docs/index.html` をブラウザーで開くと、通信なしでも動作します。

## 説明の順番

最初に「この資料について」が開きます。「説明に沿って見る」で次の7画面を順に確認できます。「デモを見る」から自由に操作することもできます。

1. この資料について：対象事業、売上・利益・会員の動き・スタッフ対応の管理目的と、AIによる情報整理・報告づくりの活用案を紹介。
2. 経営概況：架空3モデルの合計を円換算で確認し、日本・マレーシアへ絞り込み。指標・グラフ・確認事項・モデル一覧は選択した国に連動。国別比較カードは両国を表示。
3. 店舗の課題：選択したモデルの現地通貨での業績、会員・対応状況を表示。ツアーではマレーシアAFモデルの退会率と未対応フォローを確認。両者の因果関係は断定しません。
4. 会員の継続支援：架空6ケースの兆候・担当・期限・進捗・確認結果を操作。経営者は店舗別の件数と対応状況、スタッフは根拠と対応履歴を確認。
5. 改善アクション：担当責任者と確認期限をデモ内で設定。
6. 効果を考える：対応率・退会率・作業時間を分けて評価。マレーシアAFモデルの継続人数と会費を仮定し、1か月分の追加会費売上をMYRで試算。
7. 導入プラン：1〜2店舗で確認・試行・評価する進め方を説明。

既存の `#intro`、`#overview` 等への直接リンクも利用できます。タスクと試算はメモリー上だけに保持し、リロードまたは「デモをリセット」で初期状態へ戻ります。

## 継続支援デモ

[会員の継続支援を開く](https://toshiokikuchi777-sudo.github.io/fhr-executive-demo/#retention)

- 2026年10月14日時点の架空6ケース（各店舗2件）。9月の月次実績・未対応19件とは別の説明用サンプルで、全会員のリスク分布ではありません。
- 来館回数は直近28日とその前28日を比較します。「前期間4回以上かつ半分以下」「14日以上来館なし」「決済の確認が必要」「更新まで30日以内」という説明用ルールで兆候を表示します。検証済みの予測モデル・退会確率ではありません。
- 担当者と期限を指定し、対応予定・連絡済み・結果記録済みを保存できます。結果記録済みには「来館再開を確認」「継続意向を確認」「退会を確認」の明示入力が必要です。それ以外は経過確認中です。
- 連絡済みを継続実績として数えず、来館再開や継続意向も将来の退会防止効果とは断定しません。記録を修正した際は最新の状態から再集計し、以前の記録を履歴に残します。
- メモは240文字まで。入力はこのブラウザーのメモリー内のみで、再読み込み・リセットで消去されます。会員への実際の連絡、AI実行、通知、外部保存はありません。実際の個人情報を入力する用途ではありません。
- 本番化では本部の既存機能・国別の提供状況・データ利用条件を確認し、個人の対応情報は承認された環境、経営者には共有が認められた集計を表示する設計を検討します。

## 通貨と集計

- A：国内AFモデル／日本／JPY、B：マレーシアAFモデル／マレーシア／MYR、C：VISPO24モデル／日本／JPY。架空3モデルであり、実際の店舗数や法人別実績を表しません。
- 経営概況の合計・国別集計・推移は円換算。店舗詳細は現地通貨。異なる現地通貨を直接足し合わせません。
- `1 MYR = 30円` は説明用の固定レートです。実勢レートではなく、当月・前月・6か月の推移に同じレートを適用します。
- 3モデルの9月売上18,750,000円、費用14,820,000円、簡易営業利益3,930,000円。会員2,160人、未対応19件。
- 日本2モデルの売上13,500,000円、利益3,270,000円、会員1,552人。マレーシア1モデルの売上5,250,000円、利益660,000円、会員608人。
- 退会率は退会人数の合計 ÷ 月初会員数の合計。率の単純平均ではありません。
- 実導入では通貨換算の基準、対象期間、会員数や利益の定義をそろえます。業態が異なるモデルは単純な優劣として扱いません。

## 範囲

- AI欄は事前作成した表示例。実際のAIサービスや顧客情報には接続していません。報告の要約、変化の整理、対応案の下書きは本番導入時の構想です。
- 集計・計算はシステムが行い、AIは説明や下書きを支援する想定。提案の採用や会員への連絡は人が判断します。
- フリーリー・ヴィアーチェの経営数値、個人の会員情報、集客・予約・広告等は未連携です。
- 導入効果は保証せず、試験導入で作業時間・対応状況・会員の継続を比較し、運用費用や季節・キャンペーンの影響も確認します。
- タスク登録はデモ内のみ。通知、外部保存、実際の認証・店舗別認可・決済・バックアップは未実装です。
- 本番では各国・契約・既存システムの条件を確認し、共有が認められた経営情報を集計する設計を想定。全ての個人情報を一つのDBへ移す前提ではありません。
- 90日は導入検討の進め方の例であり、納期・費用・効果の約束ではありません。
